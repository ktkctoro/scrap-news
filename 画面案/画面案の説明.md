## いまの画面を9つの原則で点検した結果

幅375pxのスマホ画面で実際に測った数字。

| 原則 | いまの画面 |
|---|---|
| 1. 指で押しやすく | 絞り込みチップの高さ **33px**、基板の内タブ **29px**、定型質問 **29px**、「聞く」**39px**、グラフの閉じる「×」は **24×20px** で右上の隅（目安は44〜48px）。上のタブは画面の上端にあり、下までスクロールすると届かない |
| 2. 1画面に1つの目的 | 「けさ」の中に、3行・レポート2本・価格14個・記事82本・AIの朝3本・AIに聞く が全部入っている。いちばん押してほしいボタンがはっきりしない |
| 3. 読みやすさ | 画面の文字の **76% が13px未満**（11px台が多い）。16px以上は14か所だけ。薄い灰色（#8b9199）は白地で **3.2:1**（目安4.5:1）で、日なたでは読みにくい。外枠のぶん、左右が24px狭い |
| 4. 移動を単純に | 「くらべる」の中がさらに2段（スクラップ/基板 → クラス/CPU・IC…） |
| 5. 押したら反応 | 押したときの色の変化があるのは一部だけ。読み込み中は文字だけ |
| 6. 入力を減らす | 定型質問はあるが、ボタンが小さい |
| 7. 失敗しても戻れる | 取れないときの文が「data.json が読めませんでした。collect.py を実行してから…」で、使う人向けの言葉になっていない |

## 6案に共通で入れたこと

- 押すものは全部 **高さ48px以上**、間に8px。機械で測って、44px未満が0個なのを確かめた
- 文字は本文 **16px**、いちばん小さい添え書きでも13px。iPhoneの「文字サイズ」の設定にも合わせて大きくなる
- 薄い灰色を濃くした（白地で6.3:1）
- 外枠をやめて画面いっぱいに。ノッチ・ホームバーをよける
- 「画面の中の窓」をやめた
- 押すと色が変わる。読み込み中はぐるぐるが回る。読んだ記事は灰色になる。外のサイトへ飛ぶものには ↗ の印
- グラフは下から出る。「閉じる」は親指の届く下に置き、暗いところを押しても、スマホの「戻る」でも閉じる
- 切り替えはすべて同じ形（灰色の台に白いボタン）、絞り込みはすべてチップ（丸いボタン）にそろえた
- 通信できないときは前回の内容を出して「通信できませんでした。電波の良い場所で、もう一度読み込んでください」と出す。「もう一度読み込む」ボタンつき
- 更新が1日以上止まっていたら、そう知らせる
- 「AIに聞く」に、けさの3行をそのまま質問にしたボタンを足した（文字を打たずに聞ける）
- 前回選んだ分類チップ・くらべるの切り替えを覚えておく
- 変えていないもの: 色（藍・緑・朱の3色）、分類の数（5つ）、載せている中身

### D〜Fの中身のくわしいところ

  1本の記事が2つの品目に出ることがある（銅線の盗難 → 銅と法規制・業界）。
  主な相場は、品目の画面を開くとグラフが最初から出ている（押さなくてよい）
- **案E** はじめて開いたときは、取得元の「前回比」とここ1日の記事で「変わったこと」を出す。

## どれを選ぶか

**いちばんのおすすめは、変わらず案C。** この仕組みの目的は「**朝いちに、スマホで、1分で確認する**」こと。
開いた1画面で、銅建値・鉄・金・ドル円・けさの3行・記事の1本目まで見えて、
スクロールなしで「きょう何か動いたか」が分かる。いちばん押してほしいボタン（記事を読む）も1つに絞れている。

ほかの案が合うのはこんなとき:

| こういう使い方なら | 合う案 |
|---|---|
| 銀・ビットコイン・日経平均・NYダウも毎朝かならず見る | 案B |
| 毎朝読む量をとにかく減らしたい。同じ記事を二度読みたくない | 案E |
| 朝だけでなく、お客さんが品物を持ってきたときにも開いて相場と同業の値を見る | 案D |
| 考えずに、決まった順番で見たい | 案F |
| 見た目が変わるのは困る。押しやすくなれば十分 | 案A |

組み合わせもできる。とくに相性がよいのは:

- **案C ＋ 案Eの「見終わった」**：案Cの1画面目はそのままに、見出しの横に「新」の印を付け、
  前回見たあとの記事だけに絞れるようにする
- **案C ＋ 案Dの品目画面**：案Cの銅建値や鉄を押すと、グラフだけでなく同業の価格と記事までまとめて出す
- **案B の「くらべる」に案Fの「売り先で差が大きい品目」**を足す

## 採用するときの手順（後日のセッション向け）

1. 選んだ案のHTMLを `index.html` として置く
2. 中の `fetch('../data.json?t=' + Date.now())` を `fetch('./data.json?t=' + Date.now())` に戻す。
   `build_page.py` の `FETCH_CALL` と一字一句同じにすること（ちがうと `build_page.py` がエラーで止まる）
3. `<script id="baked-data" …>`（見本用に入れたデータ。とても長い1行）を消す。
   `build_page.py` が同じ名前で入れるので、残すと二重になる
4. `?offline` の試し機能は残してよい（圏外の見え方を確かめられる）
5. `CLAUDE.md` の「画面の機能」と `引き継ぎ書.md` を書き直す
6. `index.html` を push すると、毎朝の収集も1回走る（ワークフローが `index.html` の変更を見ているため）

公開されるのは `index.html` と `data.json` だけ（ワークフローの「公開するファイルだけまとめる」）。
この「画面案」フォルダは push しても公開ページには載らない。
