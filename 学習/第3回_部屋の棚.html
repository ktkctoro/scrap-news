AIのためのフォルダ設計　第3回

部屋の中を「棚」で分ける

第1回で部屋の選び方、第2回で部屋の置き場所を学びました。今回は部屋の中の片付け方です。

1全部が1つの山だと、AIはさわりすぎる

AIは、部屋の中の物を見て「これは直してよい物か」を自分で判断します。何もかも1つの山に積んであると、さわってはいけない物まで、親切心で直してしまいます。

そこで、物を種類ごとに「棚」に分けて、棚ごとに約束を決めます。scrap-news の部屋の中を6つの棚に分けると、こうなります。

棚たとえるとAIとの約束
① 道具工具箱直してよい
② 注文票人が書く紙人が書く。AIは勝手に書きかえない
③ できあがり品機械が作った物手でさわらない。道具を動かせば作り直される
④ 張り紙・日誌ルールと記録最初に読む。分かったことは書き足す
⑤ 試作品試作の箱本番とまぜない。決まったら箱ごと捨てる
⑥ 金庫合い鍵・暗証番号部屋に置かない

この表は、張り紙（AGENTS.md）に書いておくと効きます。scrap-news の張り紙の「構成」の表が、まさにこれです。

2できあがり品は「さわらない」。でも貯金箱はこわさない

data.json は毎朝、機械が作り直します。手で直しても次の朝には消えるので、張り紙に「自動生成。手で触らない」と書いてあります。

ただし例外があります。history.json も機械が作る物ですが、毎朝1枚ずつコインを入れている貯金箱のような記録です。消すと3ヶ月分の積み上げがゼロに戻ります。

こういう「機械が作るけれど捨ててはいけない物」は、張り紙にはっきり書いておきます。scrap-news では「毎朝コミットして引き継ぐ（消すと積み上げがゼロに戻る）」と書いてあります。

3合い鍵は、ガラス張りの部屋に置かない

パスワードや、有料サービスを使うための「鍵」は、部屋（フォルダ）に置きません。

scrap-news はだれでも中をのぞける「公開」の部屋です。ここに鍵を置くと、世界中に見せてしまいます。前に使っていた Claude API の鍵は、部屋の中ではなく GitHub の金庫（Secrets という設定）に入れていました。この置き方が正解です。

4名前は「何をするか」で付ける

○ よい名前
  • collect.py（集める）
  • check_data.py（確かめる）
  • build_page.py（ページを作る）
✕ よくない名前
  • 新しいファイル.py
  • 最終版_本当に最終.py
  • collect_old2.py

名前を見るだけで役割が分かると、AIは中を開かずに見当をつけられます。「古い版」や「最終版」をファイル名で残すのはやめましょう。どれが本物か、AIにも人にも分からなくなります。変更の記録は git が取ってくれます（第5回でくわしく）。

5引っ越しは慎重に

棚を並べかえたくなっても、すでに動いている物をむやみに移さないでください。

たとえば collect.py を別のフォルダに移すと、毎朝の自動実行を決めている collect.yml に書いてある「住所」が古いままになり、次の朝に止まります。移すときは、先にAIに聞くのが安全です。

collect.py を別のフォルダに移したら、ほかのどのファイルの住所を直す必要がありますか？まだ移さずに、一覧だけ出してください。

6やってみよう

scrap-news の部屋を開いた Claude Code に、次のように頼んでみてください。自分の部屋の棚がどうなっているか、AIが表にしてくれます。

このフォルダのファイルを「道具・注文票・できあがり品・張り紙と日誌・試作品・金庫」の6つの棚に分けて表にしてください。さわってはいけない物には印をつけてください。ファイルは変更しないでください。

最後の「ファイルは変更しないでください」が大事です。見るだけの頼みごとには、これを付けておくと安心です。

第3回のまとめ

  1. 部屋の中は6つの棚に分けて、棚ごとに約束を決める
  2. できあがり品はさわらない。でも積み上げの記録（貯金箱）はこわさない
  3. 合い鍵は部屋に置かない。公開の部屋ならなおさら
  4. 名前は「何をするか」で付ける。「最終版」は名前で残さない
  5. 動いている物の引っ越しは、先にAIに影響を聞いてから
